# 智测云：系统架构与核心设计

## 1. 产品边界

智测云定位为高校课堂的**随堂知识回顾与形成性检测工具**，不是综合考试平台。系统仅处理选择、判断和简短填空题，教师审核是发布前的必要步骤。

核心闭环：

```text
课堂内容 → AI／演示生成 → Schema 校验 → 教师编辑审核 → 发布
       → 学生结构化作答 → 服务端评分 → 个人解析与班级统计 → CSV 导出
```

## 2. 为什么使用 Assessment Schema

系统不让模型直接输出 HTML 或 React 代码，而是让模型生成受约束的结构化数据。统一 Schema 使同一份测验可以用于：

1. 教师编辑器；
2. 学生作答表单；
3. 服务端自动评分；
4. 逐题与知识点统计。

每道题包含：题型、题干、选项、答案、解析、知识点和分值。生成时由服务端分配 ID 和分值，避免模型计算总分错误。

## 3. AI 意图控制策略

### 输入约束

教师必须提供课程、主题和至少 10 个字的课堂内容，并选择题量、题型、难度与建议用时。

### Prompt 约束

- 只允许客观题，不生成计算过程、证明或论述题；
- 题目应依据教师提供的课堂内容；
- 每道题必须提供答案、解析和知识点；
- 选择题使用 A–D 选项 ID；
- 填空题只接受简短、明确的术语或事实；
- 仅返回 JSON，不返回 Markdown；
- 同一知识点复用完全一致的 `knowledgePoint`，避免近义表述造成分组拆分。

### 输出防线

```text
模型 JSON → JSON 提取 → 题量检查 → 服务端补充分值与 ID
        → Zod 业务规则校验 → 知识点分组与题型排序 → 重新分配分值
        → 教师审核 → 才允许发布
```

模型请求失败或数据不合法时明确报错，不静默替换为演示生成。

### 题目排列规则

最终排列由服务端确定，不依赖模型是否主动遵守排序要求：

1. 知识点分组保持首次出现顺序，尽量保留教学逻辑；
2. 同一知识点的题目集中排列；
3. 组内按单选 → 多选 → 判断 → 填空排序；
4. 同一题型的多道题保持原始相对顺序；
5. 排序完成后重新分配分值，总分保持 100。

## 4. 自动评分设计

评分函数是纯函数，输入教师端保存的题目和学生答案，输出总分、答对题数与逐题结果。

- 单选／多选／判断：全对得分，否则 0 分；
- 多选题：规范化顺序并去重后比较；
- 填空题：Unicode NFKC 规范化，忽略英文大小写与多余空格，支持等价答案；
- 未作答：0 分；
- 总分：由服务端根据当前题目重新汇总，浏览器不能指定分数。

## 5. 答案隔离

教师 API 返回完整题目，学生页面使用 `toPublicQuiz` 显式移除：

- `answer`；
- `explanation`。

学生提交后，服务端才使用完整题目评分，并在成绩页展示正确答案与解析。`public-quiz.test.ts` 和端到端冒烟测试共同验证该边界。

## 6. 数据模型

### Quiz

- 基本信息：课程、主题、原始课堂内容、难度、建议用时；
- 状态：`draft`、`published`、`closed`；
- 生成来源：`ai` 或 `demo`；
- 题目数组与创建、更新、发布时间。

### Submission

- 测验 ID、虚拟姓名、可选学号；
- 结构化答案；
- 服务端计算的得分、满分与答对题数；
- 提交时间。

发布后的题目不可修改，避免历史作答与评分标准不一致。填写相同学号的学生不能重复提交同一测验。

## 7. 持久化与并发

当前使用本地 JSON 文件实现轻量持久化：

- 写操作串行进入 Promise 队列；
- 先写唯一临时文件，再通过重命名原子替换；
- 读取时重新执行 Schema 校验。

该方案适合单机比赛演示和快速复现。当前未实现账户体系、学校级权限或多实例数据库，不作为这些能力的声明。

## 8. 安全与质量措施

- 密钥仅保存在服务端环境变量；
- 学生答案限制数量和长度；
- 重复学号拦截；
- CSV 对公式开头字符进行转义，并提供 UTF-8 BOM；
- 学生演示数据使用虚拟姓名与学号；
- 测试覆盖评分边界、总分分配、答案隔离和统计；
- 冒烟测试覆盖创建、发布、满分、零分、重复提交和导出。
