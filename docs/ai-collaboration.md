## 迭代 3：学生作答与答案隔离

**对应提交：`47e72ce feat: 实现学生在线作答与即时成绩反馈`**

### 开发意图

学生通过链接完成选择、判断和填空题；作答前不能获得标准答案，提交后由服务端评分并展示逐题解析。

### AI 实施与修改

- 添加公开学生作答页；
- 使用 `toPublicQuiz` 删除答案和解析字段；
- 学生答案以结构化数据提交；
- 服务端校验必答题、答案长度和学号重复提交；
- 服务端重新计算分数，不信任浏览器；
- 成绩页展示学生答案、标准答案、解析和知识点。

### 真实问题与修复

- 类型检查发现学生组件误用了包含标准答案的 `Question` 类型；
- 改为 `PublicQuiz["questions"][number]`，让类型系统也表达答案隔离边界；
- 添加公开数据测试，验证序列化结果不包含答案解析。

## 迭代 6：真实模型返回格式兼容与修复

### 用户反馈

> “生成的题目未通过校验，请调整要求后重试……我已经填写了真实的 API Key 和 Base URL。”

### 真实排查过程

1. 在不输出密钥的前提下检查 `.env.local`，确认服务已识别真实配置；
2. 使用默认课堂内容复现，接口返回 HTTP 422；
3. 详细校验路径显示 `stem` 缺失，说明不是密钥或网络错误，而是模型输出字段与解析器不一致；
4. 检查 Prompt，发现虽然描述了业务要求，但没有完整展示每道题的 JSON 字段模板。

### AI 修改与验证

- 在 Prompt 中增加完整 JSON 示例，明确 `stem`、`type`、`options`、`answer`、`explanation`、`knowledgePoint`；
- 兼容 `question`、`choices`、`correctAnswer`、`analysis` 等常见模型字段别名；
- 校验失败时显示具体题号和字段路径，不再只有笼统提示；
- 添加 3 项模型输出兼容测试，完整测试增至 15 项并全部通过；
- 使用用户配置的真实模型重新生成：HTTP 201，6 道题、题型顺序正确、总分 100、答案和解析完整。

- 新增分组、题型顺序、稳定性和总分测试，完整测试增至 17 项。

## 迭代 8：从 JSON 文件切换到 MySQL 持久化

### 用户反馈

> “代码修改了吗，现在数据应该需要持久化到数据库里了。”

此前只执行了初始化 SQL，业务代码仍写入 JSON。AI 明确承认这一状态，并在本次迭代中完成真实数据访问层替换，而不是把“建表成功”当成“应用已接入”。

### AI 修改与验证

- 安装 Drizzle ORM 与 mysql2，建立带连接池的 MySQL 数据访问层；
- 按初始化表结构建立 Drizzle Schema 映射；
- 保持原有 `listQuizzes`、`createQuiz`、`createSubmission` 等函数接口，页面和 API 无需重写；
- 测验与题目在同一事务中写入，学生提交与逐题答案在另一事务中写入；
- 使用 MySQL 唯一索引和应用层检查共同防止重复学号；
- 教师登录接入前，使用禁止登录的本地系统账号作为数据归属；
- 增加 `/api/health` 数据库健康检查；
- 配置本机 `DATABASE_URL`，密钥仍保留在被 Git 忽略的 `.env.local` 中；
- 17 项单元测试、TypeScript 检查和生产构建全部通过；
- 真实 HTTP 冒烟测试后查询 MySQL：6 道题、总分 100、2 份提交、12 条逐题答案，满分和零分均正确，重复学号被拦截。
