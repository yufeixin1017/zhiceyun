# 智测云演示视频脚本

建议成片约 **7 分 20 秒**，输出为 **MP4、1080p**。视频按真实使用流程展开，其中约 **2 分 40 秒**展示 AI 协同开发、问题定位与验证过程。

## 录制前准备

- 服务器运行最新代码，`zhiceyun` 与 `zhiceyun-tunnel` 均正常；
- 一段真实课堂讲义和可用的模型接口；
- 公网演示地址：https://luis-gratuit-validation-iii.trycloudflare.com；
- 测试教师账号和至少两份不同成绩的虚拟学生提交；
- 一部使用 4G/5G 的手机；
- GitHub 提交记录、开发过程文档和测试终端。

录制画面不应出现真实 API Key、数据库密码、私钥或学生敏感信息。

---

## 0:00–0:30｜项目背景

**画面：**公网首页，随后进入教师工作台。

**讲解参考：**

> 随堂测验通常需要教师临时出题、收集答案并统计掌握情况，重复工作比较多。智测云把课堂内容转成结构化客观题，由教师审核发布，学生用手机作答，系统自动评分并生成班级分析。

展示项目仓库和公网地址。

## 0:30–1:30｜课堂内容与 AI 出题

**画面：**创建测验页面。

**操作：**输入真实课程名称、课堂主题和讲义要点，选择 6 道题、四种题型、适中难度和 10 分钟限时，点击“AI 生成测验”。

**讲解参考：**

> 系统没有让模型直接生成网页，而是要求它返回结构化数据。每道题都包含题干、题型、选项、答案、解析和知识点，系统再将这些数据渲染成可编辑、可作答的表单。

这里展示真实模型生成，不使用预置题目代替。

## 1:30–2:25｜审核、排序与发布

**画面：**题目编辑页和分享页。

**操作：**展开同一知识点的一组题，展示单选—多选—判断—填空的顺序；修改一道题的题干或解析，展示总分 100 分，保存并发布，最后展示链接和二维码。

**讲解参考：**

> AI 负责生成初稿，教师负责最终审核。服务端会按知识点分组，并统一整理题型顺序。发布后题目锁定，所有学生都按同一套标准评分。

## 2:25–3:30｜手机流量作答

**画面：**手机扫码、作答页和成绩解析页。

**操作：**关闭手机 Wi-Fi，用 4G/5G 扫码，输入虚拟姓名和学号，完成选择、判断和填空题，展示倒计时并提交。

**讲解参考：**

> 学生不需要注册，也不受同一 Wi-Fi 限制。作答前页面不会收到标准答案，提交后由服务端统一评分。超时提交会保留，并标记为超时，方便教师识别。

展示成绩、错题和解析。

## 3:30–4:25｜教师统计与逐题分析

**画面：**教师结果页。

**操作：**展示平均分、最高分、及格率和超时提交；点击一名学生查看逐题答案；展开一道题查看各选项学生名单和完整答案组合；导出 CSV。

**讲解参考：**

> 教师既可以按学生查看作答，也可以按题目查看全班分布。这样能直接定位错误较多的题目和需要再次巩固的学生，而不只是看到一个总分。

## 4:25–7:05｜AI 协同过程复现（2 分 40 秒）

**画面：**原始开发会话、代码、测试输出和 Git 提交。

### 第一段：模型字段校验失败（约 50 秒）

展示真实报错：

```text
stem: expected string, received undefined
```

**讲解参考：**

> 接入真实模型时，题目一直无法通过校验。检查确认密钥正常后，发现模型使用了 question 等字段，而系统要求 stem。处理方式是补全 Prompt 模板，同时兼容常见字段名。修改后，真实接口返回 201，生成了 6 道题，总分 100 分。

展示 `ai-generator.ts` 和提交 `f4d5351`。

### 第二段：从 JSON 到 MySQL（约 50 秒）

**讲解参考：**

> 数据库表创建完成后，应用仍然写 JSON。随后使用 Drizzle 和事务替换存储层，保留原来的页面和 API。最终数据库实际保存了 6 道题、2 份提交和 12 条逐题答案，满分和零分都正确。

展示 `store.ts`、数据库结果和提交 `bdf11b3`。

### 第三段：教师登录与权限隔离（约 60 秒）

**讲解参考：**

> 公网部署不能只靠登录页面保护教师端。项目使用 scrypt 保存密码哈希，MySQL 保存会话哈希，并在页面、API 和查询层同时检查 teacherId。第二名教师访问别人的测验返回 404，学生公开作答返回 200。

展示 `auth.ts`、`auth-accounts.ts`、会话表和权限测试结果，提交为 `d699a73`。

最后执行：

```bash
git log --oneline
pnpm test
pnpm typecheck
```

**讲解参考：**

> 这些提交都对应真实问题和修复过程，不是最后一次性上传完整项目。目前项目有 28 次功能迭代提交和 35 项单元测试。

## 7:05–7:30｜架构与总结

**画面：**架构说明、服务状态和 README。

**操作：**展示 `/api/health`、`zhiceyun`、`zhiceyun-tunnel` 的运行状态，以及 README 的复现步骤。

**讲解参考：**

> 项目使用 Next.js、Drizzle 和 MySQL，部署在 Ubuntu 上，通过 Cloudflare 提供公网访问。数据库使用 UTC 存储时间，页面按北京时间显示。智测云的重点不是单独调用一次模型，而是把 AI 生成、教师审核、学生作答和自动评阅连成完整流程。

结束画面：公网地址、GitHub 仓库和“感谢观看”。
