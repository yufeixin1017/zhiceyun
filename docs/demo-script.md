# 智测云 5–8 分钟演示视频脚本

**建议成片时长：约 7 分 20 秒**
**录制规格：MP4、1920×1080（1080p）**
**AI 协同复现部分：约 2 分 40 秒，满足不少于 2 分钟的要求**

## 录制前准备

- Ubuntu 上运行最新代码，`zhiceyun` 与 `zhiceyun-tunnel` 均正常；
- 使用真实大模型 API，准备一段真实课堂讲义；
- 准备教师账号和一份已发布测验；
- 准备至少两份不同成绩的虚拟学生提交；
- 准备一部手机，关闭 Wi-Fi，使用 4G/5G 验证公网扫码；
- 打开 GitHub 提交历史、AI 协同 Prompt 演进记录和测试终端；
- 不在画面中出现 API Key、数据库密码或真实学生敏感信息。

---

## 0:00–0:30｜项目定位与课堂痛点

**画面：**公网地址下的智测云首页，随后切到教师工作台。

**口播：**

> 一节课结束后，教师通常还需要手动出题、收集答案并统计掌握情况。智测云面向高校课堂的随堂知识回顾，用 AI 生成客观题，由教师审核发布，学生在线作答，系统自动评分并生成学情分析。它解决的是课堂反馈慢、出题和统计重复劳动多的问题。

**操作：**展示项目仓库地址和公网演示地址。

---

## 0:30–1:30｜真实课堂内容与 AI 出题

**画面：**教师创建测验页。

**操作：**

1. 输入真实课程名称、课堂主题和讲义要点；
2. 选择 6 道题、单选/多选/判断/填空、适中难度；
3. 设置答题限时 10 分钟；
4. 点击“AI 生成测验”。

**口播：**

> 教师不需要逐题设计字段，只要描述教学内容。系统要求模型返回结构化 Assessment Schema，而不是直接生成网页代码。每道题都包含题干、题型、选项、答案、解析和知识点。

**注意：**必须展示真实模型生成，不使用预置题目代替。

---

## 1:30–2:25｜教师审核、排序与发布

**画面：**题目编辑页和发布分享页。

**操作：**

1. 展开同一知识点的一组题，展示单选—多选—判断—填空的排列；
2. 修改一道题的题干或解析；
3. 展示选择题答案、填空题等价答案、总分 100 分；
4. 保存草稿并发布；
5. 展示作答链接和二维码。

**口播：**

> AI 只负责初稿，教师保留最终审核权。服务端会按知识点分组，并按固定题型顺序整理题目。发布后题目锁定，保证所有学生使用同一评分标准。

---

## 2:25–3:30｜学生用手机流量扫码作答

**画面：**先用手机扫码，再展示手机作答页面和结果页。

**操作：**

1. 手机关闭 Wi-Fi，使用 4G/5G；
2. 扫描教师分享的二维码；
3. 输入虚拟学生姓名和学号；
4. 完成选择、判断和填空题；
5. 展示倒计时并提交；
6. 查看成绩、错题和解析。

**口播：**

> 学生不需要注册账号，也不受同一 Wi-Fi 限制。作答前页面不会收到标准答案，答案提交到服务端后才进行评分。超时提交会标记为“超时”，但仍保留成绩和统计。

---

## 3:30–4:25｜教师统计与逐题分析

**画面：**教师结果页。

**操作：**

1. 展示平均分、最高分、及格率和超时提交；
2. 点击一名学生，查看其逐题答案、正误和解析；
3. 展开“题目与标准答案”中的一道题；
4. 展示各选项选择人数、完整答案组合和对应学生名单；
5. 导出 CSV。

**口播：**

> 教师不仅能看到总分，还能按学生或按题目双向分析，定位需要再次讲解的知识点和具体学生。

---

## 4:25–7:05｜AI 协同过程复现（2 分 40 秒）

**画面：**原始 AI 会话、`智测云-AI协同Prompt演进记录.md`、代码和 Git 提交。

### 第一段：AI 输出字段校验失败（约 50 秒）

展示原始报错：

```text
stem: expected string, received undefined
```

**口播：**

> 我第一次接入真实模型时，模型返回的字段与 Schema 不一致。AI 先检查密钥和服务配置，再通过真实请求定位到 stem 缺失，随后补充 JSON 模板并兼容 question、choices、correctAnswer 等字段。

展示 `ai-generator.ts` 和真实接口返回：

```text
HTTP 201，6 道题，总分 100
```

展示提交：`f4d5351`。

### 第二段：从 JSON 到 MySQL 持久化（约 50 秒）

**口播：**

> 数据库表建好后，我追问“代码修改了吗”，发现应用仍在写 JSON。AI 使用 Drizzle 和事务替换数据访问层，保持原 API 不变，再通过数据库实际记录验证。

展示 `store.ts`、事务代码和查询结果：

```text
6 道题、2 份提交、12 条逐题答案，满分 100、零分 0。
```

展示提交：`bdf11b3`。

### 第三段：教师登录与权限隔离（约 60 秒）

**口播：**

> 教师登录不是只做一个页面。AI 使用 scrypt 保存密码哈希，MySQL 保存会话哈希，并在页面、API 和查询层同时校验 teacherId。第二名教师访问别人的测验会返回 404，学生公开作答仍返回 200。

展示 `auth.ts`、`auth-accounts.ts`、会话表，以及越权测试结果。

展示提交：`d699a73`，并补充手机号登录和注册入口的后续迭代。

### 测试与演进证明

执行：

```bash
git log --oneline
pnpm test
pnpm typecheck
```

**口播：**

> 这些提交分别对应真实需求和 Bug 修复，不是一次性上传全部代码。目前共有 28 次功能迭代提交和 35 项单元测试。

---

## 7:05–7:30｜架构、部署与总结

**画面：**架构说明、服务器服务和 README。

**操作：**

1. 展示 Next.js＋Drizzle＋MySQL 架构；
2. 展示 `/api/health`；
3. 展示 `zhiceyun`、`zhiceyun-tunnel` 服务状态；
4. 展示 README 的 10 分钟复现步骤。

**口播：**

> 项目以 Next.js 为全栈框架，MySQL 持久化，Cloudflare 提供公网访问。数据库统一使用 UTC 存储，页面按北京时间展示。智测云的核心不是简单调用一次模型，而是通过 Prompt 约束、Schema 校验、教师审核、服务端评分和可复现验证构成完整闭环。

结束画面：项目仓库、公网演示地址和“感谢观看”。
