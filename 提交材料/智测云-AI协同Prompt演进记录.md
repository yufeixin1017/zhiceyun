# 智测云开发过程记录：三次关键迭代

我做智测云时，没有一开始就把所有功能定死，而是在真实使用中不断发现问题、调整需求、修复 Bug。下面三次迭代最能说明我是怎样向 AI 描述需求、判断修改建议，以及最后用测试和真实数据确认结果的。

项目仓库：https://github.com/yufeixin1017/zhiceyun

---

# 第一次：真实模型返回的题目无法通过校验

## 问题是怎么出现的

接入真实模型后，我以为只要填好 API Key 和 Base URL 就能直接出题，但页面却提示：

> “生成的题目未通过校验，请调整要求后重试。”

我当时向 AI 提出的问题是：

> “为什么报错了呢，生成的题目未通过校验，请调整要求后重试。你看一下 .env.local，我已经填写了真实的 API Key 和 Base URL。”

## 我是怎么排查的

我先确认配置确实已经被服务读取，没有继续折腾密钥。随后用“过拟合与模型泛化”这段课堂内容重新调用了一次接口，拿到更具体的错误：

```text
HTTP 422
path: ["stem"]
message: Invalid input: expected string, received undefined
```

问题不在网络，也不在 API Key，而是模型返回的字段和系统约定的不一致。系统要求题干字段叫 `stem`，模型却可能返回 `question`、`title` 或其他写法，所以校验直接失败。

## 我是怎么修改的

我做了三项调整。

第一，我把希望模型返回的 JSON 结构完整写进 Prompt，明确要求每道题都必须包含：

- `type`：题型；
- `stem`：题干；
- `options`：选项；
- `answer`：答案；
- `explanation`：解析；
- `knowledgePoint`：知识点。

题目 ID 和分值不再让模型生成，而是统一由服务端分配。

第二，我增加了字段兼容处理。例如：

- `question`、`questionText`、`题干` 统一转成 `stem`；
- `choices`、`选项` 统一转成 `options`；
- `correctAnswer`、`答案` 统一转成 `answer`；
- `analysis`、`解析` 统一转成 `explanation`。

第三，我没有因为模型格式不稳定就放松校验。题量、题型顺序、答案是否引用已有选项、多选是否至少两个答案，仍然全部检查。出错时也会显示具体是第几道题、哪个字段有问题，方便继续修复。

## 最后是怎样验证的

修改后，我再次使用真实模型生成同一份课堂内容，接口返回：

```text
HTTP 201
题目数量：6
总分：100
题型顺序：单选、多选、判断、填空、单选、多选
题干、答案和解析均完整
```

后来我又发现同一知识点的题目会散开，于是继续要求：

> “同一知识点的题目相邻排列，并且同一知识点下的题目排列应该遵循单选—多选—判断—填空。”

我没有只依赖模型自己排序，而是在服务端统一整理题目，确保同一知识点集中、题型顺序固定。

对应提交：

```text
f4d5351 fix: 兼容真实模型题目字段并完善生成提示
682e64a feat: 按知识点分组并规范题目排列顺序
```

这次修改让我确认：调用模型只是第一步，Prompt 要写清楚结构，代码也要能处理模型输出的不确定性。

# 第二次：数据库已经建好，应用却还在写 JSON

## 问题是怎么出现的

前面我已经让系统创建好了 MySQL 数据库和表，但检查代码时发现，页面产生的数据仍然保存在 `data/database.json` 中。

我直接向 AI 提出：

> “代码修改了吗，现在数据应该需要持久化到数据库里了。”

这句话实际上是在提醒我：建好数据库不代表应用已经接入数据库，必须用真实写入来验证。

## 我是怎么修改的

我决定保留现有页面和 API，只替换底层存储，避免把已经能用的功能全部重写。

具体做了这些修改：

1. 使用 Drizzle ORM 和 mysql2 建立 MySQL 连接池；
2. 按数据库表结构建立 Drizzle Schema；
3. 用 `DATABASE_URL` 配置连接，不把账号密码提交到仓库；
4. 把 `listQuizzes`、`createQuiz`、`createSubmission` 等函数切换到 MySQL；
5. 新增 `/api/health`，直接检查数据库连接状态。

在写入方式上，我把两组操作分别放进事务：

- 创建测验时，测验和全部题目一起写入；
- 学生提交时，整次成绩和逐题答案一起写入。

这样不会出现“测验保存了，但题目只写了一半”或者“成绩有了，逐题答案却丢失”的情况。

重复学号也做了两层拦截：应用先检查一次，MySQL 再用 `(quiz_id, student_no)` 联合唯一索引兜底，避免并发请求绕过检查。

## 最后是怎样验证的

我没有只看页面是否显示成功，而是走了一遍完整流程：创建并发布测验，再分别提交一份满分答案、一份全错答案和一份重复学号答案，然后直接查询 MySQL。

数据库中的实际结果是：

```text
测验状态：published
题目数量：6
题目总分：100
学生提交：2 份
逐题答案：12 条
满分学生：100 分
全错学生：0 分
重复学号：被拦截
```

这次验证让我确认，应用已经真正使用 MySQL，而不是只把数据库当作展示用的空壳。

对应提交：

```text
0b7d7a4 feat: 初始化 MySQL 数据库与核心数据表
bdf11b3 feat: 将测验与作答数据持久化到 MySQL
```

# 第三次：教师登录和越权访问处理

## 问题是怎么出现的

早期版本里，任何人只要知道教师端地址，就能查看标准答案、学生成绩，甚至调用 AI 出题。这显然不适合公网部署，因此我提出：

> “现在完成教师登陆的开发。”

我的要求不是只增加一个登录页面，而是教师必须登录，学生继续免登录；不同教师之间也不能看到彼此的数据。

## 我是怎么修改的

我先把教师账号体系补齐：

- 首次使用时通过 `/setup` 创建教师账号；
- 原来本地系统账号直接升级为真实教师账号，已有测验和学生作答不需要迁移；
- 密码使用 scrypt 哈希保存，不保存明文；
- 登录后生成随机会话令牌，数据库只保存令牌的 SHA-256 哈希；
- 浏览器使用 HttpOnly Cookie，公网 HTTPS 下启用 Secure；
- 退出时删除会话并清除 Cookie。

权限检查放在三个地方：

1. 教师页面未登录时跳转到登录页；
2. 教师 API 未登录时返回 401；
3. 查询测验、学生提交和统计时按 `teacherId` 过滤，非本人数据返回 404。

后续我又根据实际使用体验做了几处调整：密码最低长度改为 8 位，登录方式改为手机号，登录页始终保留“立即注册”，让其他教师也能拥有独立工作台。

## 最后是怎样验证的

我在独立的 `zhiceyun_test` 数据库里测试，避免测试账号占用正式账号。

测试覆盖了：

- 未登录访问教师页面会被重定向；
- 未登录调用教师 API 返回 401；
- 初始化、登录、退出和错误密码处理正常；
- 第二名教师访问第一名教师的测验、学生详情和导出接口都返回 404；
- 学生不带 Cookie 仍能正常打开公开作答页面。

这些测试说明权限不是只把导航藏起来，而是真正在页面、接口和数据库查询中生效。

对应提交：

```text
d699a73 feat: 完成教师登录会话与数据权限隔离
2d271d8 fix: 将教师密码最低长度调整为八位
6e91786 feat: 改用手机号登录并内嵌题目作答分布
8749514 fix: 始终提供多教师注册入口
```
