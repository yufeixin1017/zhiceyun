# 智测云演示视频脚本

我准备把视频控制在 **7 分 20 秒左右**，输出为 **MP4、1080p**。我会按真实使用过程来讲，不把时间花在逐条念功能上，其中约 **2 分 40 秒**专门展示我怎样用 AI 解决开发中的问题。

## 录制前我会准备好

- 一段真实课堂讲义和一个真实可用的模型接口；
- 公网演示地址：https://luis-gratuit-validation-iii.trycloudflare.com；
- 测试教师账号和至少两份不同成绩的虚拟学生提交；
- 一部使用 4G/5G 的手机；
- GitHub 提交记录、开发过程文档和测试终端。

录制时不会出现真实 API Key、数据库密码、私钥或学生敏感信息。

## 0:00–0:30｜我为什么做这个项目

**画面：**公网首页，然后进入教师工作台。

我会这样讲：

> 我在准备随堂测验时，发现出题、收答案、评分和统计都很费时间。所以我做了智测云：输入课堂内容，AI 帮我生成客观题，我审核后发布，学生用手机作答，系统直接给出成绩和班级分析。

随后展示项目仓库和公网地址。

## 0:30–1:30｜从课堂内容生成题目

**画面：**创建测验页面。

我会输入真实课程名称、课堂主题和讲义要点，选择 6 道题、四种题型、适中难度和 10 分钟限时，然后点击“AI 生成测验”。

我会这样讲：

> 我没有让模型直接写网页，而是要求它返回结构化数据。每道题都有题干、题型、选项、答案、解析和知识点，系统再把这些数据渲染成可以编辑和作答的表单。

这里必须展示真实模型生成，不使用预置题目代替。

## 1:30–2:25｜审核、修改和发布

**画面：**题目编辑页和分享页。

我会先展开同一知识点的一组题，让评委看到单选、多选、判断、填空按顺序排列，再修改一道题的题干或解析，展示总分 100 分，最后保存并发布。

我会这样讲：

> AI 只是帮我完成初稿，最终是否适合学生作答还是由我判断。发布以后题目会锁定，所有学生都按同一套标准评分。

最后展示作答链接和二维码。

## 2:25–3:30｜学生用手机流量作答

**画面：**手机扫码、作答页和成绩解析页。

我会关闭手机 Wi-Fi，用 4G/5G 扫码，输入虚拟姓名和学号，完成选择、判断和填空题，再展示倒计时并提交。

我会这样讲：

> 学生不需要注册，也不用和我连接同一个网络。作答前页面拿不到标准答案，提交后由服务端统一评分。超时提交会保留，但会标记为超时，方便我区分学生的提交情况。

随后展示成绩、错题和解析。

## 3:30–4:25｜我怎样查看学生的掌握情况

**画面：**教师结果页。

我会依次展示平均分、最高分、及格率和超时提交，点击一名学生查看逐题答案，再展开一道题查看各选项学生名单和完整答案组合，最后导出 CSV。

我会这样讲：

> 我既可以按学生查看他的作答，也可以按题目查看全班分布。这样我能直接看到哪道题错误较多、哪些学生需要再巩固，而不只是得到一个总分。

## 4:25–7:05｜我怎样用 AI 解决三个开发问题（2 分 40 秒）

**画面：**原始开发会话、代码、测试输出和 Git 提交。

### 第一段：模型字段对不上（约 50 秒）

我会展示当时的报错：

```text
stem: expected string, received undefined
```

然后这样讲：

> 我刚接入真实模型时，题目一直无法通过校验。我先确认不是密钥问题，再让 AI 帮我分析返回结构，发现模型用了 question 等字段，而系统要求 stem。于是我补全 Prompt 模板，同时兼容常见字段名。最后真实接口返回 201，生成了 6 道题，总分 100 分。

展示 `ai-generator.ts` 和提交 `f4d5351`。

### 第二段：数据库建好了，数据却在 JSON 里（约 50 秒）

我会这样讲：

> 后来我检查时发现，虽然数据库表已经创建，应用仍然写 JSON。于是我让 AI 用 Drizzle 和事务替换存储层，保留原来的页面和 API。最后数据库里实际保存了 6 道题、2 份提交和 12 条逐题答案，满分和零分都正确。

展示 `store.ts`、数据库结果和提交 `bdf11b3`。

### 第三段：教师登录与越权访问（约 60 秒）

我会这样讲：

> 公网部署后，教师端不能只靠一个登录页面保护。我使用 scrypt 保存密码哈希，MySQL 保存会话哈希，并在页面、API 和查询层同时检查 teacherId。第二名教师访问别人的测验会返回 404，但学生公开作答仍然是 200。

展示 `auth.ts`、`auth-accounts.ts`、会话表和权限测试结果，提交为 `d699a73`。

最后执行：

```bash
git log --oneline
pnpm test
pnpm typecheck
```

并补充一句：

> 这些提交都对应我真实遇到的问题和修复，不是最后一次性把完整代码传上去。目前项目有 28 次功能迭代提交和 35 项单元测试。

## 7:05–7:30｜部署和总结

**画面：**架构说明、服务状态和 README。

我会展示 `/api/health`、`zhiceyun`、`zhiceyun-tunnel` 的运行状态，再翻到 README 的复现步骤。

最后这样讲：
